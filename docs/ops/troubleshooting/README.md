# 트러블슈팅

K3s에서 Vercel 서버리스 + Supabase로 옮기며 마주친 문제와 해결 과정을 기능별로 정리했다.
같은 함정을 다시 밟지 않도록 **증상 → 원인 → 해결 → 측정값** 순으로 남긴다.

- 대상: `AID-FIT/Backend`, `AID-FIT/Frontend`
- 운영: https://aidfit-backend.vercel.app · https://aidfit-frontend.vercel.app

## 가장 값어치 있는 세 가지

**리전 불일치가 19배를 만든다** ([01](./01-deployment-infra.md#1-함수-리전과-db-리전이-어긋나-19배-느렸다))
요청은 서울 엣지로 들어오는데 함수가 미국 동부에서 돌고 DB는 서울에 있었다. 서버리스는 요청마다
커넥션을 새로 열어 **연결 수립만으로도 태평양을 여러 번 건넜다.** `x-vercel-id`로 확인한다.

**내용 해시로 경로를 정하면 파일이 공유된다** ([03](./03-image-storage.md#3--삭제할-때-참조-카운팅이-필요하다))
중복이 사라지는 대신 서로 다른 사용자가 하나의 파일을 쓰게 된다. 삭제할 때 참조 카운팅을
안 하면 **남의 사진이 깨진다.**

**서버리스는 응답 후 함수를 동결한다** ([04](./04-ai-integration.md#2--업로드가-ai-호출을-동기로-기다리고-있었다))
`BackgroundTasks`가 완료된다는 보장이 없다. 응답 이후 작업이 필요하면 큐, Cron, 또는 별도 요청이
필요하다.

## 서버리스로 옮길 때 체크리스트

각 문서 끝에 영역별 체크리스트가 있다. 이전을 시작하기 전 최소한 이 정도는 확인한다.

- [ ] 함수 실행 리전을 DB 리전과 맞췄는가
- [ ] 커넥션 풀과 prepared statement를 pooler에 맞게 껐는가
- [ ] 로컬 디스크에 쓰는 코드가 남아 있지 않은가
- [ ] 외부 AI 호출이 사용자 요청을 동기로 붙잡고 있지 않은가
- [ ] 무거운 네이티브 의존성(PyTorch 등)이 배포 대상에 들어 있지 않은가
- [ ] `.env.example`에 실제 값이 들어가지 않았는가
- [ ] 환경변수 추가 후 재배포했는가
- [ ] 검색 결과가 화면마다 다르게 보정돼야 하는지 확인했는가
- [ ] 서버로 보내는 조건 중 클라이언트에서 거를 수 있는 것이 섞여 있지 않은가
- [ ] 로컬 파이썬 버전이 배포 런타임과 같은가
- [ ] 기본값이 배포 환경에서 실제로 동작하는 값인가
- [ ] 예외를 삼키는 `except`에 트레이스백 로그가 있는가
- [ ] ANN 인덱스의 탐색 폭이 `LIMIT` 이상인가
- [ ] 컬럼을 추가했다면 **배포 전에** DDL을 적용했는가 (`create_all`은 기존 테이블을 바꾸지 않는다)
