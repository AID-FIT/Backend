# 배포·인프라 트러블슈팅

K3s에서 Vercel 서버리스로 옮기며 인프라 계층에서 겪은 문제.

**핵심 한 줄** — 서버리스는 리전·디스크·실행 시간이 전부 기본값에 맡겨져 있고, 그 기본값이 우리 상황과 어긋나 있었다.

---

## 1. 함수 리전과 DB 리전이 어긋나 19배 느렸다

이 이전 작업에서 가장 임팩트가 컸던 문제다.

### 증상

DB를 한 번만 조회하는 엔드포인트가 **3.2초** 걸렸다. DB를 쓰지 않는 헬스체크마저 0.4초였다.

### 원인 추적

응답 헤더가 결정적이었다.

```
x-vercel-id: icn1::iad1::8pw5v-...
             ^^^^  ^^^^
             엣지   함수 실행 리전
```

요청은 서울(`icn1`) 엣지로 들어오는데 **함수는 미국 동부(`iad1`)에서 실행**되고 있었다. Supabase DB는 서울(`ap-northeast-2`)에 있다.

매 요청이 이렇게 돌았다.

```
한국 사용자 → icn1 엣지 → iad1 함수 → (태평양) → 서울 DB
                                    ← (태평양) ←
           ← icn1 ← iad1 ←
```

여기에 서버리스 특성이 겹쳤다. 커넥션 풀을 유지할 수 없어 `NullPool`을 쓰는데, 그러면 **요청마다 새 커넥션**을 연다. Postgres 커넥션 수립은 TLS 핸드셰이크와 인증에 여러 왕복이 필요하다. 쿼리 1회가 아니라 **연결하는 것만으로도 태평양을 여러 번 건넜다.**

### 해결

```json
// vercel.json
{ "regions": ["icn1"] }
```

### 결과

```
x-vercel-id: icn1::icn1::65vpv-...
```

| | 이전 | 이후 |
| --- | ---: | ---: |
| `/users/me` (DB 1회) | 3.2초 | **0.17초** |
| `/health` (DB 미사용) | 0.40초 | **0.066초** |

### 교훈

**서버리스에서 함수 리전은 기본값을 믿지 말고 명시한다.** DB가 특정 리전에 고정돼 있으면 반드시 맞춘다.
`x-vercel-id` 헤더로 실제 실행 리전을 확인할 수 있다.

```bash
curl -s -D - -o /dev/null https://<host>/api/v1/health | grep -i x-vercel-id
```

## 2. 서버리스에는 쓸 수 있는 디스크가 없다

### 증상

업로드한 이미지가 다음 요청에서 사라졌다. 배포 직후에는 부팅 중 `settings.upload_dir.mkdir()`에서 예외가 났다.

### 원인

두 가지가 겹쳤다.

1. 함수 파일시스템은 **읽기 전용**이다. `/tmp`만 쓸 수 있다.
2. `/tmp`에 써도 **요청 간 유지되지 않는다.** 인스턴스가 매번 새로 뜬다.

기존 코드는 `uploads/`에 저장하고 `/uploads`를 StaticFiles로 서빙했다. K3s에서는 볼륨이 붙어 동작했지만 서버리스에서는 성립하지 않는다.

### 해결

- 저장은 객체 스토리지로 옮겼다 → [이미지 스토리지 문서](./03-image-storage.md)
- 부팅 시 디렉터리 생성 실패를 허용했다. 읽기 전용에서 죽으면 안 된다.

```python
# app/main.py
try:
    settings.upload_dir.mkdir(parents=True, exist_ok=True)
    app.mount("/uploads", StaticFiles(directory=settings.upload_dir), name="uploads")
except OSError:
    pass
```

## 3. `maxDuration`을 명시하지 않으면 느린 호출이 잘린다

### 배경

실제 Gemini를 켠 뒤 추천 1건이 12초까지 걸렸다. `GEMINI_TIMEOUT_SECONDS=60`인데 함수 실행 한도를 두지 않으면, 느린 호출이 **플랫폼 타임아웃에 먼저 걸려** 502/504가 난다.

### 걸림돌

`functions` 설정을 추가하려 했는데 충돌했다. **`builds`/`routes`(레거시 형식)는 `functions`와 함께 쓸 수 없다.**

### 해결 — `rewrites` 방식으로 마이그레이션

```json
{
  "regions": ["icn1"],
  "functions": { "api/index.py": { "maxDuration": 60 } },
  "rewrites": [{ "source": "/(.*)", "destination": "/api/index.py" }]
}
```

> ⚠️ 라우팅 형식을 바꾸는 변경이다. 배포 후 반드시 확인한다. `/health`, `/openapi.json`, 실제 엔드포인트를 모두 찔러보고 `x-vercel-id`로 리전 유지도 확인했다.

Hobby 플랜의 `maxDuration` 상한은 60초다.

## 4. 요청 본문 4.5MB 제한

Vercel 서버리스 함수의 **요청 본문은 4.5MB로 제한**된다. 요즘 폰 사진은 이를 넘기기 쉽다.

현재는 클라이언트 리사이즈가 없어 **큰 사진은 업로드가 실패한다.** 미해결 과제로 남아 있다.

---

## 5. 불필요한 네이티브 의존성 제거

`passlib[bcrypt]`가 `requirements.txt`에 있었지만 실제로는 어디서도 쓰이지 않았다(OAuth로 전환한 뒤 주석 처리된 상태). 네이티브 빌드를 유발할 수 있어 의존성과 import를 함께 제거했다.

> 서버리스 빌드에서는 네이티브 확장이 실패 지점이 되기 쉽다. 이전 전에 **실제로 쓰이는지** 확인하고 정리한다.

---

## 체크리스트

- [ ] 함수 실행 리전을 DB 리전과 맞췄는가 (`x-vercel-id`로 확인)
- [ ] 로컬 디스크에 쓰는 코드가 남아 있지 않은가
- [ ] `maxDuration`을 외부 호출 타임아웃보다 크게 잡았는가
- [ ] 라우팅 설정 형식을 바꿨다면 전 경로를 재검증했는가
- [ ] 요청 본문 크기 제한을 넘길 입력이 있는가
- [ ] 쓰이지 않는 네이티브 의존성을 정리했는가
