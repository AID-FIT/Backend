AID-FIT Agent & LLM 작업 공유

이번 작업은 추천 백엔드에 LangGraph 기반 Agent 흐름을 연결하고, VLM, RAG, LLM 경계를 명확한 계약으로 분리한 뒤, 최종 추천 문구 생성 단계에서 Gemini를 사용할 수 있도록 정리한 작업입니다. 팀원들이 전체 흐름과 파일별 역할을 빠르게 파악할 수 있도록 핵심만 요약했습니다.

작성 기준: 현재 로컬 최종 수정본 문서 위치: docs/agent_llm_work_summary.html 주요 범위: Agent, VLM, RAG, LLM, 테스트
Agent

추천 파이프라인 구성

AidFitAgentPipeline이 입력 검증, 이미지 분석, 의도 분류, 검색, 랭킹, 최종 응답 생성을 순서대로 실행합니다.

Contracts

AI 모듈 간 계약 추가

app/schemas/ai.py에 VLM, RAG, Agent error 스키마를 추가해 모듈 간 입출력 형식을 검증합니다.

LLM

Gemini 연결 준비

LlmService가 Gemini generateContent를 호출하고, 결과를 백엔드 응답 형식에 맞게 보정합니다.

한 줄 설명

사용자의 추천 요청이 들어오면 Agent가 이미지와 옷장 정보를 참고해 검색 대상을 정하고, RAG 결과를 사용자 취향과 옷장 메타데이터 기준으로 재정렬한 뒤, LLM이 실제 후보 상품 안에서만 자연스러운 한국어 추천 응답을 작성하도록 만들었습니다.

요청 처리 흐름

추천 API는 기존 FastAPI 구조를 유지하고, 내부 추천 로직만 Agent 파이프라인으로 확장했습니다. 텍스트만 있는 요청은 VLM을 건너뛰고, 이미지가 있으면 VLM 분석 후 검색 단계로 이동합니다.

1. API recommendations.py에서 추천 요청을 받습니다.
2. Service RecommendationService가 이미지 입력을 정규화하고 Agent를 호출합니다.
3. Context 이미지, 옷장 아이템, 사용자 프로필 여부를 확인합니다.
4. Retrieval 의도에 따라 closet, musinsa, hybrid 검색으로 라우팅합니다.
5. Ranking RAG 점수에 취향, 옷장 매칭, 쿼리 관련성 보너스를 반영합니다.
6. LLM 후보 상품만 기반으로 최종 추천 사유와 스타일 가이드를 생성합니다.

팀별 연동 포인트

VLM 팀

교체해야 할 위치

VlmService._external_analyze_many() 내부를 실제 이미지 분석 API 호출로 바꾸면 됩니다.

  • 입력: image_urls: list[str]
  • 출력: VLMResponse 형식
  • 중요 필드: category, color, material, fit, mood, sense_of_season
RAG 팀

교체해야 할 위치

RagService._external_search_request() 내부를 실제 검색 API 또는 vector DB 호출로 바꾸면 됩니다.

  • 입력: RAGRequest 형식
  • 출력: RAGResponse 형식
  • Musinsa 상품은 product_url이 필수입니다.

LLM 안정성 처리

LLM은 문장을 자연스럽게 만드는 역할만 맡고, 상품 데이터의 사실성은 백엔드가 다시 보장하도록 했습니다. 즉, Gemini가 상품명이나 URL을 잘못 만들더라도 최종 응답은 RAG 후보 상품 기준으로 보정됩니다.

  • Gemini에는 최대 8개 후보만 전달해 prompt 크기를 제한합니다.
  • responseMimeType: application/json과 responseSchema로 JSON 출력을 요구합니다.
  • _normalize_llm_response()가 LLM 추천을 후보 상품 ID 또는 이미지 URL로 다시 매칭합니다.
  • 후보에 없는 상품을 추천하면 제거하고, 남는 추천이 없으면 empty 응답으로 처리합니다.
  • 최종 응답은 AgentResponse로 다시 검증합니다.
Gemini raw JSON -> JSON parse -> candidate_items 기준 재매칭 -> AgentResponse 검증 -> RecommendationResponse HTTP body

환경 변수

기본값은 mock AI입니다. 실제 Gemini 호출을 확인하려면 로컬 .env에서 아래 값을 설정합니다.

USE_MOCK_AI=false GEMINI_API_KEY=your_key_here GEMINI_MODEL=gemini-2.5-flash GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta GEMINI_TIMEOUT_SECONDS=30

실제 모델명은 app/core/config.py와 .env.example 값이 일치해야 합니다. 모델명이 잘못되면 Gemini 호출에서 404 또는 model not found 오류가 날 수 있습니다.

로컬 실행 방법

LLM 단계만 빠르게 확인할 때:

& "$env:USERPROFILE\miniconda3\python.exe" scripts\run_llm_only.py

네트워크 없이 mock LLM으로 확인할 때:

& "$env:USERPROFILE\miniconda3\python.exe" scripts\run_llm_only.py --mock

백엔드 API 전체 흐름으로 확인할 때:

& "$env:USERPROFILE\miniconda3\python.exe" -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
