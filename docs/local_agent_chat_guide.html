AID-FIT Agent 로컬 채팅 사용 가이드

Windows PowerShell에서 프론트엔드, FastAPI 서버, PostgreSQL을 실행하지 않고 현재 LangGraph Agent를 직접 호출해 대화와 분기 흐름을 확인하는 방법입니다.

Windows PowerShell LangGraph Agent Mock / Gemini DB 저장 없음 업데이트: 2026-08-23
빠른 시작 실행 모드 대화 명령어 실행 옵션 Trace 읽기 실행 흐름 문제 해결

1. 빠른 시작

권장

실제 Gemini 대화

Gemini가 의도 분류, 질의 정제, 검색 계획, 최종 답변을 생성합니다.

cd C:\Users\kyle0\Develops\Backend
.\scripts\run_agent_chat.ps1 -Mode Gemini -Trace
오프라인

Mock 대화

외부 API를 호출하지 않고 그래프 연결과 세션 문맥만 빠르게 확인합니다.

cd C:\Users\kyle0\Develops\Backend
.\scripts\run_agent_chat.ps1 -Mode Mock -Trace
별도로 실행하지 않아도 되는 것

프론트엔드, uvicorn, Docker, PostgreSQL, DB 초기화 스크립트는 필요하지 않습니다.

최초 실행

  1. 저장소 루트에서 PowerShell 명령을 실행합니다.
  2. .venv가 없으면 실행기가 자동으로 Python 가상환경을 만듭니다.
  3. 필요한 패키지가 없으면 requirements.txt를 자동 설치합니다.
  4. 나 > 프롬프트가 나타나면 질문을 입력합니다.

2. 실행 모드 선택

Auto

-Mode Auto

.env의 USE_MOCK_AI 값을 따릅니다. -Mode를 생략해도 Auto입니다.

Mock

-Mode Mock

외부 요청 없이 결정론적 mock LLM/VLM/RAG 경로로 실행합니다. 연결 확인과 테스트에 적합합니다.

Gemini

-Mode Gemini

실제 Gemini API로 LLM 단계를 실행합니다. .env에 유효한 API 키가 필요합니다.

현재 어댑터 범위

Gemini 모드에서도 의도 분류·질의 정제·검색 계획·최종 문장 생성은 실제 Gemini를 사용하지만, VLM과 RAG의 외부 어댑터는 현재 로컬 mock 구현으로 연결됩니다.

Gemini 환경 변수

# .env
USE_MOCK_AI=false
GEMINI_API_KEY=YOUR_VALID_API_KEY
GEMINI_MODEL=gemini-3-flash-preview
GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta

API 키는 출력하거나 Git에 커밋하지 마세요. 이 저장소의 .env는 Git ignore 대상입니다.

3. 대화 중 사용할 수 있는 명령어

명령어동작사용 예
/help사용 가능한 명령어를 다시 표시합니다./help
/reset대화 내역, 후보 풀, 이미 보여준 상품 문맥을 초기화합니다./reset
/trace에이전트 분기 trace 출력을 켜거나 끕니다./trace
/image <URL>다음 질문 한 번에 이미지 URL을 첨부합니다./image https://example.com/top.jpg
/images다음 질문에 첨부될 이미지 URL 목록을 확인합니다./images
/exit현재 로컬 채팅 세션을 종료합니다./exit
후속 질문 예시

첫 추천 뒤 그중 더 저렴한 건?이라고 질문하면 대화 내역과 기존 후보를 전달합니다. trace에서 retrieval_action: reuse, rag_reused: true인지 확인할 수 있습니다.

5. Trace 읽는 방법

필드의미
intentgeneral_chat 또는 fashion_service로 분류된 현재 요청 유형입니다.
resolved_query대화 내역과 이미지 문맥을 반영해 검색 가능한 형태로 정리한 질의입니다.
retrieval_action기존 후보를 쓰는 reuse인지 새 검색을 하는 retrieve인지 나타냅니다.
candidate_scope전체 후보(all) 또는 아직 보여주지 않은 후보(unseen) 범위입니다.
retrieval_targetcloset, musinsa, hybrid 중 선택된 검색 대상입니다.
rag_reused직전 후보 풀을 실제로 재사용했는지 나타냅니다.
rag_item_count현재 턴의 최종 RAG 항목 수입니다.
candidate_pool_count후속 질문에 재사용할 수 있도록 메모리에 유지하는 전체 후보 수입니다.
shown_item_count현재 대화에서 사용자에게 이미 보여준 상품 참조 수입니다.
error성공이면 null, 실패하면 코드·메시지·발생 모듈을 표시합니다.
 
[trace]
{
  "intent": "fashion_service",
  "resolved_query": "여름용 반팔 티셔츠",
  "retrieval_action": "retrieve",
  "candidate_scope": "all",
  "retrieval_target": "musinsa",
  "rag_reused": false,
  "rag_item_count": 10,
  "candidate_pool_count": 10,
  "shown_item_count": 4,
  "error": null
}

6. 로컬 실행 흐름

1. PowerShell실행 옵션과 사용자 입력을 받습니다.
2. Python Runner서버 없이 Agent 객체를 직접 생성합니다.
3. Local Session대화와 후보 문맥을 메모리에 유지합니다.
4. LangGraph의도·정제·검색·응답 노드를 실행합니다.
5. Gemini / Mock선택한 모드로 LLM 결정을 생성합니다.
6. Terminal답변, 추천 카드 정보, trace를 출력합니다.
  • FastAPI HTTP 요청 없음
  • PostgreSQL 연결 없음
  • 프론트엔드 실행 없음
  • 대화 데이터 DB 저장 없음
  • 프로세스 종료 시 세션 초기화
  • Gemini 모드에서만 외부 LLM 호출

7. 문제 해결

Gemini

API_KEY_INVALID

.env의 GEMINI_API_KEY를 유효한 키로 교체한 뒤 새 프로세스로 다시 실행합니다.

후보

RAG 항목은 있는데 추천이 비어 있음

요청 카테고리와 로컬 mock 카탈로그 후보가 맞지 않으면 Gemini가 상품을 지어내지 않고 빈 결과를 반환합니다.

환경

Python을 찾지 못함

Python 3와 Windows Python Launcher(py)를 설치한 뒤 저장소 루트에서 다시 실행합니다.

PowerShell

스크립트 실행 정책 오류

현재 프로세스에만 우회 정책을 적용해 실행할 수 있습니다.

powershell -ExecutionPolicy Bypass `
  -File .\scripts\run_agent_chat.ps1 `
  -Mode Mock

의존성 수동 재설치

.\.venv\Scripts\python.exe -m pip install -r requirements.txt

전체 테스트 실행

.\.venv\Scripts\python.exe -m pytest -q tests -p no:cacheprovider
보안 주의

오류를 공유할 때 API 키가 포함된 .env 내용은 붙여 넣지 마세요. trace에는 키가 출력되지 않으며, 키 유효성만 별도로 확인하는 것이 안전합니다.
